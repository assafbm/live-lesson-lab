# Security, media quality and UI review

Date: 2026-11-06. Scope: recent application, signaling, AWS infrastructure and
deployment work, including the unresolved mechanical/intermittent audio report.

## Executive result

The ordinary two-person flow passes the local regression suite. This review
fixed concrete capture, validation, lifecycle and UI defects. It does **not**
establish that natural voice now sounds correct on the owner's devices, nor
that the app is ready for unrestricted real-student use.

**Deployment update:** after the owner authorized continuation, these changes
were published to the AWS pilot and the deployed smoke check passed. See the
[release record](deployment-2026-11-06.md) for scope and evidence. GitHub OIDC
publication remains blocked by an AWS Organizations policy; this was a manual
CLI deployment, and no credentials were added to source or workflows. The review
tables below describe findings at review time; the release record updates their
deployment status.

## Audio: what is known and what remains unknown

The earlier logs showed packet counters sometimes stopping while concealment
continued. Other intervals showed packets progressing. Those samples alone do
not locate the fault: possible stages include input device/processing, sender,
transport, decoder/playout, and local audio output. A connected ICE state only
confirms a connection path; it does not guarantee natural, uninterrupted speech.

The review reproduced a concrete settings bug in Chrome: an overlapping capture
of the same microphone can retain previous processing. With two test tabs using
that source, changing one tab's settings can still fail. The UI now reports this
instead of silently claiming success. Releasing the other capture lets the test
verify the requested setting. This explains why earlier controls might not have
helped; it does not prove that this caused all of the owner's audible symptoms.

The next acceptance step is a separate-device headset call with 30 seconds of
continuous speech in each direction and matching diagnostic downloads. Use the
checklist in [testing.md](testing.md). If the problem persists, use the paired
sender/receiver evidence to choose the next fix; do not force high bitrate,
disable all echo protection, or declare success from fake audio alone.

## Remaining release gates and risks

| Priority | Issue | Required next work |
| --- | --- | --- |
| Before real-user rollout | Anonymous room creation and bearer invitations | Teacher identity, server-side authorization, expiring/revocable invitations, admission policy and negative tests |
| Before real-user rollout | AWS endpoint abuse/cost controls incomplete | Distributed connection/message quotas, room limits, operational alerts and budgets; local socket limits are not equivalent |
| Before broad network support | No TURN | Select a relay with temporary scoped credentials, measure cost, and test forced-relay calls |
| Before reliable long lessons | No robust reconnect/ICE restart or teacher ownership recovery | Handle API Gateway connection lifetime, network changes and browser refresh; do not rely only on heartbeat |
| Open functional acceptance | Reported mechanical/weak/intermittent voice | Two-device listening tests and paired diagnostics; no claimed complete resolution yet |
| Before cloud release | Local changes not exercised against live AWS | Review CDK diff, publish infrastructure and matching web release, inspect headers, then repeat two-device flow |
| Before automatic publishing | Organization policy denies OIDC creation | Account administrator resolves policy; verify exact GitHub subject; activate optional role/workflow without long-lived keys |
| Toolchain exposure | CDK audit reports two moderate advisories through bundled minimatch | Track upstream fix; avoid forcing the offered incompatible downgrade. Root application audit is clean. This is not proof every dependency is risk-free |
| Compatibility | Chrome fake-media coverage only | Real Chrome/Edge and mobile browser tests, different cameras, unplug/replug, background tabs and constrained networks |
| Performance | Canvas transformation runs on the main thread | Measure high-resolution handwriting plus audio on slower devices; consider a worker-based pipeline only with evidence |
| Data lifecycle | Pilot resources use destroy-on-stack-delete policies | Revisit retention/backups before introducing durable student/lesson/recording data |
| State races | Not every AWS concurrent join/leave/failure interleaving is covered | Add service-level integration tests and idempotent recovery before scaling |

No database of lesson history, recording, scheduling, second student, SFU or AI
was added. DynamoDB remains temporary signaling state only.

## Validation performed

- `npm run check`: passed across shared, local signaling, AWS signaling and web.
- `npm run build`: passed, including the production Vite bundle.
- `npm test`: **11 passed** in the final isolated functional test run (15.7 seconds).
- Browser stability check: all three lesson scenarios repeated three times;
  **9 additional passes** in 38 seconds, without concurrent builds.
- `infra/aws`: `npm run build` and `npm run synth -- --quiet`: passed.
- Dependency review: root audit clean; infrastructure audit has the two moderate findings described above.
- `git diff --check` passed; relative links in the six principal documentation
  files resolve. A targeted scan found no AWS access-key/private-key patterns
  in source; this limited check is not a comprehensive secret-scanning guarantee.
- Screenshot inspection: desktop settings and meeting view, 390×844 portrait,
  667×375 landscape; automatic no-page-overflow and toolbar-visibility checks.
- No deployment or real microphone listening test was performed as part of this review.

Test distribution: three AWS handler cases, three protocol/statistics cases,
one real local signaling case, one microphone capability case, and three
end-to-end lesson cases. AWS SDK calls are mocked in handler tests. The browser
uses synthetic camera/audio with direct localhost ICE, so packet loss, TURN,
cloud timing, hardware acoustic behavior and audible quality are not covered.

One validation run performed alongside a build failed after the browser returned
to signaling-ready state. Concurrent writes to Vite-watched build outputs are a
likely cause; the isolated complete rerun passed. Run builds before browser tests,
not concurrently with them. The CI workflow follows this sequence.

## Naming and maintainability

New responsibilities have explicit names: `MediaQuality` summarizes statistics,
`MediaDiagnostics` presents/export summaries, and `MicrophoneSettings` is the
shared control surface. Existing camera ownership stays in `CameraSourceManager`;
outgoing pixel changes stay in `OutgoingVideoTransform`. Comments explain why
capture generations, serialization, effective-setting checks and one-source
sharing exist.

`useLessonSession` remains large. A future extraction of signaling, peer
negotiation and audio-capture ownership should preserve the new regressions;
splitting it while diagnosing audio would enlarge the change surface. AWS
generated physical names are retained to avoid resource replacement. Logical
names, tags and the resource inventory explain their purposes.
